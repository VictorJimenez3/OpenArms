## Reproduced integration defects for parent

1. **R1/R4 — Gemini tool cancellation does not revoke a queued runtime proposal.** In a fake Gemini connection wired to the real `Lab`, finish a student transcript, send a `request_action` tool call for a prepared vinegar sample, wait for its proposal, present it, then send `tool_call_cancellation` for that ID. The bridge marked the tool cancelled, but the task remained `awaiting_confirmation` with the same pending proposal and zero executions. Calling the runtime hook with the same ID, `lab.tool(sid, '_cancel_tool_request', {'tool_call_id': cid})`, immediately changed the task to `cancelled` and cleared the proposal. `GeminiBridge._downstream` currently cancels its own callback and interrupts output; the runtime correlation hook exists but the provider cancellation branch never calls it. Carry the provider ID through to that hook even if the provider callback already returned; verify other requests are unaffected and the cancelled proposal cannot be approved. The migrated tests cover the two sides independently, not this missing connection.

2. **R2/R4/D1 — Validator accepts a structurally valid plan that silently omits an unsupported clause.** Call `Lab.start_task` with “Run prepared vinegar and then measure dilution concentration.” Inject an expert returning only `inspect_scene → mock_prepared_sample(vinegar) → observe` with a readability check. The runtime creates an `awaiting_confirmation` proposal; presenting and confirming it yielded `completed` and one mock dispatch, despite leaving out the concentration request. Exact consent was still required; there was no auto-dispatch. `TaskLoop._check_context` validates the operations, freshness and bindings but does not validate coverage of the original request. The passing clarification tests prove exact routing with a cooperative expert and prevent prefix reuse; they do not prove a faulty expert is blocked. Add a fail-closed disposition for omitted/unsupported requested work, with a regression that injects a subset-only expert. Preserve a separately requested supported action as an option.

The fixtures exercise portions of R1–R5 and D1–D3 offline. Image observation here uses fake perception; active-version routing uses a synthetic evaluation receipt to set up the fixture. They are not evidence of R3’s real image path, R6/D4 improvement, actual model responsiveness, or device playback. The parent retains the whole-suite run and integration acceptance.
